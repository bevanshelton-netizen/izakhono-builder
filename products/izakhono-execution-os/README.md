# IZAKHONO EXECUTION OS

Execution layer for IZAKHONO SUPER AI.

The purpose is simple: turn an approved business objective into a controlled delivery pipeline instead of returning advice only.

## Execution loop

`OBJECTIVE → PLAN → BUILD → TEST → RELEASE → MARKET → LEADS → SALES → REPORT`

## Operating rules

- **Owned-first:** use IZAKHONO runtimes and services before external providers.
- **External providers are adapters:** never hard-code a vendor into product logic.
- **No false completion:** a stage is complete only when its acceptance evidence exists.
- **Human approval gates:** publishing, financial actions, regulated decisions and destructive operations require explicit approval.
- **No paid advertising by default:** organic distribution is the default until the owner authorizes spend.
- **Secret-safe:** browser clients never receive model/provider credentials.

## First execution templates

- Product launch
- Service launch
- Digital product sale
- Lead-generation campaign
- Website/project completion
- Internal automation

## Completion evidence

Each project records stage status and evidence links. A project cannot be marked `completed` merely because code was generated; deployment, acceptance and owner sign-off remain separate states.

## Marketing pack

The marketing stage is designed to generate a reusable campaign pack containing:

- positioning
- offer
- audience
- headline variants
- social posts
- short-form video scripts
- landing-page copy
- email/WhatsApp follow-up
- CTA and checkout link
- organic distribution checklist
- measurement plan

## Current UI

The first production-safe cockpit is a static control surface. AI execution is intentionally server-side and fail-closed; credentials and private model routes must never be placed in client JavaScript.
