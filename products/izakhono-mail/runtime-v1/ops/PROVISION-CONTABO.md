# IZAKHONO MAIL — First Public Runtime Provisioning

## Decision

Use a provider-neutral public Linux runtime. Contabo is the first candidate because its current documentation states that server port access is unrestricted by default, provides a static public IPv4, and exposes self-service PTR/rDNS management. Provider selection remains reversible.

Contabo documents public IPv4 allocation and PTR management in its Control Panel, and its firewall is inactive by default. Do not enable a provider firewall until the required mail/web ports are explicitly allowed.

## Recommended starting size

Start with **Contabo Cloud VPS 4** or equivalent:
- 4 vCPU
- 8 GB RAM
- 100 GB SSD
- public static IPv4
- IPv6 subnet preferred
- Ubuntu 24.04 LTS

This is intentionally larger than the minimum so the first production mail runtime has headroom for Rspamd, Roundcube, logs and backups. Upgrade vertically only when measured usage requires it.

## Required network contract

Allow inbound TCP:
- 22 — SSH
- 25 — SMTP server-to-server mail
- 80 — ACME HTTP-01 and redirect
- 443 — HTTPS webmail
- 465 — authenticated SMTP over TLS
- 587 — authenticated SMTP submission
- 993 — IMAPS

Keep outbound SMTP available, especially TCP 25, because direct mail delivery depends on it.

## Provisioning sequence

1. Create the VPS with Ubuntu 24.04 LTS.
2. Attach/confirm the public IPv4 and IPv6.
3. Set PTR/rDNS for the public IPv4 to `mail.izakhonoafrica.co.za`.
4. Confirm the PTR resolves back to the server hostname.
5. Confirm TCP 25/465/587/993/80/443 are reachable from the public Internet.
6. SSH into the server and install Docker Engine + Compose v2.
7. Clone `bevanshelton-netizen/izakhono-builder`.
8. Enter `products/izakhono-mail/runtime-v1`.
9. Copy `.env.example` to `.env` and set strong unique secrets.
10. Run `./ops/preflight.sh`.
11. Run `./ops/bootstrap.sh`.
12. Publish the generated DKIM record at the domain DNS provider.
13. Publish/verify A, MX, SPF and DMARC records.
14. Run the acceptance test before declaring production.

## DNS contract

Required records:

```text
mail.izakhonoafrica.co.za.    A       <PUBLIC_IPV4>
izakhonoafrica.co.za.         MX 10   mail.izakhonoafrica.co.za.
izakhonoafrica.co.za.         TXT     "v=spf1 mx -all"
_dmarc.izakhonoafrica.co.za.  TXT     "v=DMARC1; p=none; rua=mailto:postmaster@izakhonoafrica.co.za"
```

The bootstrap generates the DKIM material. Publish the exact selector/value generated by the runtime; never invent or reuse a DKIM key.

PTR:

```text
<PUBLIC_IPV4> -> mail.izakhonoafrica.co.za
```

After delivery has been proven, tighten DMARC from `p=none` toward enforcement based on observed legitimate senders.

## Secrets

Never commit `.env`, mailbox passwords, DKIM private keys, TLS private keys, or database passwords to GitHub.

The production mailbox is:

```text
bevans@izakhonoafrica.co.za
```

## Acceptance gate

Production is **BLOCKED** until all of these pass:

- A record
- MX record
- SPF
- PTR/rDNS
- TCP 25 reachable
- TCP 465 reachable
- TCP 587 reachable
- TCP 993 reachable
- HTTPS webmail
- valid TLS certificate
- mailbox login
- outbound delivery to an independent external mailbox
- inbound delivery from an independent external mailbox
- IMAPS read/send test
- DKIM validation
- DMARC validation
- backup creation
- restore test

Do not use the phrase “live mail” until the evidence exists for the complete gate.

## Recovery / provider replacement

If the provider becomes unsuitable:

1. Export/restore persistent mail data.
2. Provision another Linux/Docker host using this same runtime.
3. Reapply DNS/PTR.
4. Run preflight and bootstrap.
5. Repeat the full acceptance gate.
6. Move traffic only after verification.

The provider supplies compute and network reachability; IZAKHONO owns the runtime definition and operational contract.
