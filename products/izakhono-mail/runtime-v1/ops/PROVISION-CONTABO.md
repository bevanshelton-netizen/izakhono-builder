# IZAKHONO MAIL — First Public Runtime Provisioning

## Decision

Use a provider-neutral public Linux runtime. Contabo remains the first candidate because its published service documentation describes static public IPv4 and self-service PTR/rDNS management. Provider selection is reversible; this runbook does not authorise a provider purchase or production deployment.

## Recommended starting size

Start with Contabo Cloud VPS 4 or an equivalent owner-approved runtime:
- 4 vCPU
- 8 GB RAM
- 100 GB SSD
- public static IPv4
- IPv6 subnet preferred
- Ubuntu 24.04 LTS

This is an initial sizing hypothesis, not a measured capacity guarantee. Scale only from measured load and deliverability requirements.

## Required network contract

Allow inbound TCP:
- 22 — restricted owner SSH
- 25 — SMTP server-to-server delivery
- 465 — authenticated SMTP over TLS
- 587 — authenticated SMTP submission with STARTTLS
- 993 — IMAPS
- 80/443 — owned IZAKHONO HOST EDGE only

Keep outbound TCP 25 and 443 available. Confirm the provider does not block outbound SMTP. Do not expose Stalwart admin/JMAP listeners publicly; ports 18080 and 18081 are loopback-only.

## Provisioning sequence

1. Create the public runtime with Ubuntu 24.04 LTS and an owner-controlled SSH key.
2. Attach/confirm the public IPv4 and IPv6.
3. Set PTR/rDNS for the public IPv4 to mail.izakhonoafrica.co.za.
4. Confirm PTR resolves back to the mail hostname.
5. Confirm TCP 25/465/587/993 are reachable from an independent network.
6. Install Docker Engine and Compose v2 using the official installation instructions.
7. Clone bevanshelton-netizen/izakhono-builder.
8. Deploy the owned products/izakhono-host/docker-compose.owned.yml stack first. It owns public ports 80/443 and creates the shared izakhono-mail network.
9. Enter products/izakhono-mail/runtime-v1, copy .env.example to .env, and set unique owner-held secrets. Never commit .env.
10. Run ./ops/preflight.sh, then ./ops/bootstrap.sh. The script reuses the canonical HOST Stalwart service and starts Roundcube; it refuses to start a second Stalwart container.
11. Complete Stalwart's first-run setup through a loopback-only SSH tunnel. Configure an ACME provider with HTTP-01.
12. As owner administrator, create the mail domain and enable automatic DKIM plus the configured ACME provider. Export the exact DNS zone file.
13. Create the restricted provisioner role from config/stalwart-provisioner-role.json, create the dedicated service account, and issue an Inherit-mode API key. Never place System Administrator credentials in the application environment.
14. Publish the exact DNS zone material generated by Stalwart; verify A, MX, SPF, DKIM, DMARC and PTR records. Only then provision customer mailboxes.
15. Run ./ops/PROVIDER-ACCEPTANCE.sh, independent inbound/outbound delivery tests, mailbox login tests, encrypted backup and a restore test.

## DNS contract

At minimum, publish:

    mail.izakhonoafrica.co.za.       A       <PUBLIC_IPV4>
    webmail.izakhonoafrica.co.za.    A       <PUBLIC_IPV4>
    izakhonoafrica.co.za.            MX 10   mail.izakhonoafrica.co.za.
    izakhonoafrica.co.za.            TXT     "v=spf1 mx ~all"
    _dmarc.izakhonoafrica.co.za.     TXT     "v=DMARC1; p=none; rua=mailto:postmaster@izakhonoafrica.co.za"
    <selector>._domainkey.izakhonoafrica.co.za. TXT <EXACT_STALWART_DKIM_VALUE>

The actual DKIM selector/value must come from the Stalwart domain configuration. Publish it exactly. After delivery is proven and legitimate senders are inventoried, tighten DMARC from monitoring toward enforcement.

PTR:

    <PUBLIC_IPV4> -> mail.izakhonoafrica.co.za

## Secrets

Never commit .env, mailbox passwords, Stalwart admin credentials, DKIM private keys, TLS private keys, database passwords, age identities or backup decryption keys.

The initial CEO mailbox target is bevans@izakhonoafrica.co.za. Mailbox passwords are generated by the Provisioner and returned once; they are not stored in evidence files.

## Acceptance gate

Production is BLOCKED until all of these pass with timestamped evidence:

- A records for mail and webmail
- MX, SPF, DKIM and DMARC records
- PTR/rDNS
- TCP 25/465/587/993 reachable
- valid SMTP/IMAP TLS certificates
- authenticated SMTP submission
- outbound delivery to an independent external mailbox
- inbound delivery from an independent external mailbox
- IMAPS login and Roundcube login
- DKIM signature validation and DMARC alignment
- encrypted backup creation
- successful restore and post-restore mail delivery
- FORTRESS access controls, audit trail and rollback proof

A running container, a created mailbox, or a successful CI run is not proof of public mail delivery.

## Recovery / provider replacement

1. Create an encrypted backup with the owner-controlled age recipient.
2. Provision the replacement runtime and deploy HOST EDGE.
3. Restore using the matching age identity; keep .env and secrets separate.
4. Reapply PTR and public DNS only after the replacement host passes preflight.
5. Run the full mail acceptance gate.
6. Move traffic only after the replacement has proven inbound/outbound delivery and restore integrity.

The provider supplies replaceable compute and network reachability; IZAKHONO owns the mail runtime, provisioning logic, DNS intent, security policy and evidence contract.
