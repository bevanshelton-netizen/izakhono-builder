# Evidence source ledger

Every guide must have an internal source ledger before editorial review. The bibliography in the PDF is a reader-facing subset; this ledger is the audit record behind the guide.

## Required record fields

| Field | Requirement |
|---|---|
| Source ID | Stable ID such as S001; never reuse an ID after removing a source. |
| Exact title | Copy the source's displayed title accurately. |
| Publisher / author | Named organisation or author responsible for the source. |
| Canonical URL | Direct HTTPS URL; record redirects or archived versions separately. |
| Source type | Primary law/regulation, official guidance, original research, academic review, reputable secondary source, or other. |
| Publication / update date | Exact date where available; otherwise record unknown rather than guessing. |
| Access date | Date the reviewer actually opened and checked the source. |
| Claims supported | Claim IDs and a short description of what the source actually supports. |
| Relevant passage | Page, section, paragraph, table or heading locator. Do not copy substantial protected text. |
| Jurisdiction / population | Country, region, age group, sector or population to which the source applies. |
| Reliability / limitations | Method, authority, recency, conflicts, scope and known limitations. |
| Rights / reuse notes | Facts are not the same as permission to reuse text, images, tables or layouts. Record any licence or permission evidence. |
| Verification status | pending, verified, stale, inaccessible, contradicted or rejected. |
| Reviewer / reviewed date | Human identity and date for verification; no automated system may impersonate a reviewer. |

## Evidence rules

1. Prefer current primary sources for law, regulation, official procedures, public statistics and institutional requirements.
2. Prefer original research and systematic reviews for research claims; record methodology and population limits.
3. Use secondary sources for context, not as a substitute for the controlling primary source.
4. Open every source. A plausible URL, search snippet or AI-generated citation is not verification.
5. Map each material factual claim to one or more source IDs. Mark unsupported claims for removal, qualification or further research.
6. Record contradictory evidence and uncertainty. Do not cherry-pick a convenient source.
7. Recheck time-sensitive claims immediately before release and set a review date for the edition.
8. Record the source's jurisdiction and population. Do not generalise South African guidance to all countries.
9. Public access does not grant permission to reproduce protected text, images, diagrams, tables, course material or page design.
10. Keep the internal ledger with the manuscript and product record. Only publish the concise bibliography and appropriate attribution in the PDF.

## Release gate

A source marked pending, inaccessible, stale or contradicted cannot silently support a material claim. The editor must resolve it or remove/qualify the claim. Rights review is a separate gate from factual verification. High-stakes guides also require qualified specialist review; an AI-generated ledger is not that review.

## Claim IDs

Use stable IDs such as CLAIM-001 in the manuscript review notes. A claim record should identify the exact claim, its location in the draft, source IDs, verification result, required qualification and reviewer. Do not mark a claim verified solely because a source is listed.
