# IZAKHONO Portfolio Recovery & Integration Register

**Release train:** 2026-11-28  
**Source of truth:** this register is a recovery index, not a claim that every project is production-ready.  
**Operating principle:** OWNED-FIRST. BUILD. ENGINEER. AUTOMATE. DEPLOY WITH EVIDENCE.

## Executive finding

The connected accounts contain multiple separate product codebases and deployment projects. The first discovery pass found 8 GitHub repositories, more than 160 Vercel projects across two result pages, and 4 Supabase projects. Some are ready deployments, some have failed or missing deployments, and some are merely project shells. A READY deployment is not proof of public DNS, customer acceptance, legal readiness, backups or operational production readiness.

## Portfolio rules

1. Preserve each product's own name, purpose, data boundary, users and domain.
2. Reuse shared IZAKHONO platform capabilities through versioned APIs/SDKs; do not merge separate applications into one monolith.
3. FORTRESS Compliance Intelligence is a FORTRESS module and may integrate with FORTRESS BANK, CSD, CLEAR, SETTLE, GLOBAL ASSET MANAGEMENT, DIGITAL ASSETS, WEALTH and CONNECT through least-privilege contracts.
4. FAISReady remains an RE examination preparation and education platform. It is not a compliance case-management product.
5. NexTradeFinX is documented as multilingual financial-market education, market intelligence and paper trading. It is not assumed to be a licensed live brokerage.
6. Edu-Build ECD360 keeps its strict child/guardian privacy boundaries, centre-scoped permissions and server-authoritative money controls.
7. SHELTONAIR remains separate from PDF publishing and other brands.
8. The $7 Topic PDF Publishing Programme remains a distinct international digital publishing storefront; do not combine it with the separate books/author collection or other websites.
9. IZAKHONO HOST and IZAKHONO MAIL are owned-infrastructure programmes. Vercel previews do not constitute proof that the owned runtime or public mail service is live.
10. No infrastructure, paid integration, provider subscription, domain purchase or commercial spend is authorised by this recovery register.
11. Never promote a regulated service to live operation without the applicable legal entity, licence/authorisation, approved partners, controls and professional sign-off.
12. Never expose secrets in source control, browser bundles, issue comments or generated manifests.

## Shared IZAKHONO capabilities — integration contract

Build once in the owned Builder and expose through versioned, optional adapters:

- Identity / organisation / tenant context
- RBAC, MFA and session policy
- Audit events and evidence references
- Document storage abstraction and versioning
- Notification and email delivery abstraction
- Billing/payment orchestration adapters (provider-neutral; per-project enablement)
- Job queue, retries, idempotency and webhook verification
- Observability, health checks and release evidence
- Localisation, accessibility and design tokens
- Build/test/package/deploy pipeline with explicit project-specific roots

Each application owns its business schema and domain rules. Shared modules must never grant cross-product data access by default. Integration is via narrow APIs, scoped tokens, tenant-aware contracts and contract tests.

## Release evidence required for every app

Record repository + branch + commit; Vercel project + root directory; build command/output; environment-variable names (never values); database/migration version; tests; deployment URL and target; domain/DNS/TLS check; security/privacy review; backup/restore status; customer acceptance; and owner approval. A deployment marked READY is only one item in this checklist.
