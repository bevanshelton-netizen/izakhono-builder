# IZAKHONO Authoritative DNS Fabric

This directory defines the owner-controlled authoritative DNS layer for IZAKHONO.

## Design

- BIND 9 is the reference authoritative DNS engine.
- Public authoritative service uses UDP/TCP 53 only for DNS.
- Recursive resolution is disabled on authoritative servers.
- Zone transfers are restricted to explicitly configured secondary servers.
- Customer records are generated by the IZAKHONO Provisioner; operators should not hand-edit generated zones.
- DNSSEC is an activation gate: zones must not be advertised as DNSSEC-secured until signing and DS delegation have been externally verified.
- Cloud DNS providers may be used as temporary/reversible fallback, but they are not the source of truth for an IZAKHONO-owned zone.

## Production topology

Use at least two independently reachable authoritative nameservers before public delegation:

- `ns1.<owned-dns-domain>` — primary/hidden-primary or authoritative primary
- `ns2.<owned-dns-domain>` — secondary

Do not publish placeholder hostnames or private RFC1918 addresses.

## Cutover gate

A domain is **PUBLIC_DNS_LIVE** only after all of these are externally verified:

1. Parent registry/registrar delegates the domain to the IZAKHONO NS set.
2. NS and SOA answers are returned by independent public resolvers.
3. Direct queries to every advertised authoritative server succeed over UDP and TCP 53.
4. The SOA serial is consistent across authoritative servers.
5. No recursion is available on authoritative servers.
6. Required A/AAAA/CNAME/MX/TXT records resolve correctly.
7. If DNSSEC is enabled, DNSKEY/RRSIG and parent DS validate end-to-end.

Until those checks pass, documentation and automation must report `PUBLIC_DNS_STATUS=UNVERIFIED`.

## Provisioner contract

The Provisioner should treat DNS as an explicit state machine:

`REQUESTED -> ZONE_CREATED -> PUBLISHED -> DELEGATED -> VERIFIED -> DNSSEC_VERIFIED`

A failed external check must not advance the state.

## Security requirements

- Never expose transfer keys, TSIG secrets, API credentials, or zone-signing private keys in Git.
- Never enable open recursion.
- Restrict AXFR/IXFR to authenticated secondary peers.
- Keep management/API interfaces off public DNS listener addresses.
- Keep production deployment references immutable.
- Record evidence for every public cutover.
